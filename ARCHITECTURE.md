# Architecture of `cdd-sh`

`cdd-sh` employs a hub-and-spoke compiler architecture where a central Abstract Syntax Tree (AST) facilitates independent, bidirectional transforms between various targets.

## The AST Hub (`ast.json`)

At the core of the toolchain is `ast.json`. Instead of inventing a proprietary intermediate language, `ast.json` mirrors the exact shape of an **OpenAPI 3.2.0 JSON object**. This guarantees that no semantic meaning is lost when mapping specifications into components.

## The Spokes (`src/*`)

The project is broken into distinct modules under `src/`. Each module is responsible for a specific domain concept and implements two interfaces: `parse.sh` and `emit.sh`.

```
src/
├── openapi/    # Handles AST <-> OpenAPI spec (mostly pass-through/formatting)
├── routes/     # Handles AST <-> curl-based API client functions
├── classes/    # Handles AST <-> JSON data validators
├── webhooks/   # Handles AST <-> Inbound listener stubs
├── docstrings/ # Handles AST -> Markdown documentation
├── tests/      # Handles AST -> Executable mock curl tests
└── mocks/      # Handles AST <-> Sample JSON payloads
```

### 1. `emit.sh` (AST -> Output)
Emitting is primarily handled using **`jq` string interpolation and reduction**. `emit.sh` reads `ast.json` and outputs highly structured, template-driven POSIX shell code. 

For complex structures like classes, `cdd-sh` uses external `.jq` filters (e.g., `src/classes/emit.jq`) to prevent bash quoting nightmares and keep the pipeline clean.

### 2. `parse.sh` (Output -> AST)
Parsing relies on **comment annotations** (e.g., `# @function`, `# @class`) generated by `emit.sh`. 

When a user edits the code, `parse.sh` uses **`awk` state machines** to read these annotations, extract shell variables, and assemble a temporary JSON stream (`.jsonl`). It then uses `jq` to merge these updates back into the central `ast.json`, overwriting or appending to the relevant OpenAPI objects (`paths`, `components.schemas`, etc.).

## Execution Flow & Environment

- **`cdd.sh`**: The main entry point. It handles argument dispatching, loading the standard prelude, and invoking the correct handler (e.g., `handle_emit_routes`).
- **The Prelude**: Every script includes a standardized POSIX shell preamble that establishes absolute directory paths (`LIBSCRIPT_ROOT_DIR`) and provides strict error handling (`set -feu`). It avoids bashisms (like `local`, arrays, or `[[`) entirely.
